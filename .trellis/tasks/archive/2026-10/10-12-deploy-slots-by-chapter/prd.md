# 出阵名额按章节递增

## Goal

招募系统上线后，每关剧情武将已经占满（甚至超出）出阵名额，招募来的小兵 / 武将没有位置上场。
按章节给每关出阵上限加额外名额，并自动在原阵型附近补出可用的出阵位，让每关稳定留出 2–3 个空位给招募单位。

## 现状数据（不带招募时：出阵名额 − 剧情武将候选数）

章节取关卡数据自带的 `stage.chapter` 字段（取空格前的前缀）：

| 章节 | 关卡 | 原名额 | 空位 |
|---|---|---|---|
| 序章 | 颍川 | 4 | 0 |
| 第一章 霸王诞生 | 汜水关 → 吕布包围（14 关） | 5–11 | 0 ~ −1 |
| 第二章 河北之争 | 徐州入侵 → 柳城 | 9–10 | −2 ~ −3 |
| 第三章 三国鼎立 | 博望坡 → 马超迎击 | 10 | −3 |
| 第四章（忠臣之道 / 霸业） | z_ 前 6 关 / j_ 前 3 关 | 10–12 | −3 |
| 终章（魔王复活 / 天下统一） | z_ 后 6 关 / j_ 后 11 关 | 11–12 | −2 ~ −3 |

## Requirements

- 章节 = `stage.chapter` 的前缀（序章 / 第一章 / 第二章 / 第三章 / 第四章 / 终章），两条路线同名章节共用一档。
- 每章一个额外名额增量，集中在一张配置表里，可直接改数字调整。
- 增量（已确认 +2/+3/+4/+5/+6 递增，封顶 +6）：序章 +2、第一章 +3、第二章 +4、第三章 +5、第四章 +6、终章 +6。
  - 用户原提议 +2 / +4 / +6 …（线性），后期会到 22 人，存在平衡 / 节奏 / 地图空间问题，故缩小步长。
  - 原型验证：全部 57 关都能在原出阵位 4 格内找够新位置；加名额后每关空位 1–4。
- 额外名额对应的出阵位自动生成：从原出阵位向外寻找格子，要求在地图范围内、该关所有可能上场兵种都能站（至少一种兵种可通行）、不与敌军 / 友军 / 其他出阵位重叠。
- 单关若找不到足够的格子，按实际能找到的数量加名额，不报错。
- 关卡可单独覆盖（例如显式写 `deploy.max` 或额外 `slots`），覆盖优先于自动补位。
- 必须出阵武将、默认阵容、营中带入的阵容（`initialDeploy`）逻辑不变，只是 `max` 变大。
- 整备界面（阵容页分页）能正常显示更多候选与名额。

## Acceptance Criteria

- [ ] 所有正式关卡 `planDeploy(stage).max` = 原名额 + 本章增量（地图空间不足的关卡除外，并在测试输出中列出）。
- [ ] 新增出阵位全部可通行、不与任何敌军 / 友军初始位置及原出阵位重叠。
- [ ] 不带招募时每关默认阵容与改动前一致（剧情武将不被挤掉、必须出阵武将齐全）。
- [ ] 招募单位可以在整备中选上场，并出现在战场的新增出阵位上。
- [ ] `node scripts/camp-smoke.mjs` 等现有回归脚本通过；`npm run build` 通过。

## Out of Scope

- 不调整敌军数量 / 难度。
- 不改招募价格与候选规则。
